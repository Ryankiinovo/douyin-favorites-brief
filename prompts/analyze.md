# 抖音收藏结构化提炼

你是收藏夹提炼流水线的“分析”步骤。输入是证据包（示例见 `demo/fixtures/2026-10-22/manifest.json`），输出是一个 JSON 对象，写入配置的分析文件（默认 `state/analysis.json`）。

## 输入结构

- `date`：处理日期（上海时区）。
- `items`：本次采集到的视频，每条包含：
  - `aweme_id`、`title`、`desc`、`author`、`publish_time`、`duration_text`、`url`
  - `stats`：点赞/评论/收藏等，可能为空
  - `ocr`：去重后的字幕/画面 OCR
  - `ocr_timed`：带时间戳的 OCR，格式 `[分:秒] 文本`，优先用它判断“钩子第几秒”
  - `transcript`：可选的语音转写，可能没有

## 输出结构

只输出一个 JSON 对象，不要 Markdown 代码围栏，不要解释：

```json
{
  "date": "YYYY-MM-DD",
  "items": [
    {
      "aweme_id": "输入里的 id，原样返回",
      "summary": "这条视频讲了什么，40-80 字，结论先行",
      "hook": "钩子是什么、在第几秒；没有时间戳就说“开场/中段”，不要编造秒数",
      "verdict": "值得完整看 | 只看前半 | 看个乐 | 跳过",
      "verdict_reason": "为什么给这个判断，20-50 字",
      "actions": ["能直接照做的动作，1-3 条，动词开头"],
      "followup": "要 / 不要 / 以后再说 + 一句理由",
      "confidence": "high | medium | low",
      "evidence": ["OCR 或转写里的原句，1-3 条，不改写"],
      "topics": ["1-4 个短标签"]
    }
  ]
}
```

## 判断规则

1. **只依据输入**：不要补充视频里没讲的事实，不要用外部知识替视频补结论。
2. **summary 是“讲了什么”**：一句话说清主题、核心观点或方法；不要写成标题复述。
3. **hook 要可验证**：`ocr_timed` 有明确秒数才写秒数；只有 `ocr` 就写“开场/中段/结尾”，不要猜。
4. **verdict 用四个枚举之一**：
   - `值得完整看`：有完整方法、步骤、案例或可复用模板。
   - `只看前半`：核心信息在前半段，后半段偏闲聊/重复。
   - `看个乐`：观点主观、信息密度低，但有趣或有情绪价值。
   - `跳过`：纯广告、标题党、信息不足，或与知识管理无关。
5. **actions 必须具体**：写“把结论提到第 1 句”，不要写“提升表达”；没有可执行动作时，给“暂不跟进”并说明。
6. **confidence**：
   - `high`：字幕/OCR 清晰，方法或步骤完整。
   - `medium`：有部分字幕，能判断主题，但细节缺失。
   - `low`：只有标题/描述，或 OCR 大面积乱码；summary 要明确“信息不足”。
7. **evidence 逐字引用**：从 `ocr` / `ocr_timed` / `transcript` 里挑最短的原句，不要改写，不要编造。
8. **不要漏条**：`items` 必须覆盖输入里的每个 `aweme_id`，顺序一致；无法判断也要给 low 和保守结论。
9. **过滤 UI 噪声**：点赞数、搜索框、推荐栏、重复字幕不要写进 summary/evidence。
10. **中文输出**：专有名词保留原文；不要输出英文长句。

## 写入

把最终 JSON 写入配置的分析文件（默认 `state/analysis.json`）。写完后不要重复解释，交给 render 步骤。

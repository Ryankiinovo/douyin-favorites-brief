# 关键决策记录

## ADR-001 公开展示层与私有采集层分离

**背景**：完整链路依赖个人登录态、平台页面和本机环境。把采集器包装成公开工具，会带来平台条款、账号安全、长期维护和“别人跑不起来”的承诺问题。

**决定**：公开产品定义、架构、提示词、渲染器和合成示例；采集器、登录器、OCR 二进制、真实运行态不公开。

**代价**：不能承诺“一键复现”完整链路；换来的是边界清晰，展示重点回到产品判断和可维护性。

## ADR-002 专用 Chrome + Playwright，而不是宿主内置浏览器

**背景**：平台登录态需要跨天复用；内置浏览器适合交互，不适合作为每日定时任务的持久会话。

**决定**：私有采集层使用 Playwright persistent context，把会话放在本机非同步目录；宿主只负责触发和提炼。

**代价**：多一个 Chrome 窗口、依赖本机 Chrome、登录过期要人工扫码。换来的是定时任务能无人值守复用会话，且登录态不进入对话。

## ADR-003 OCR 优先，不接 ASR

**背景**：第一版要避免引入额外模型服务、API Key 或转写费用。

**决定**：优先使用页面字幕/文案；没有字幕时用关键帧 + macOS Vision OCR；结果带 `confidence`。

**代价**：口播为主、画面文字少的内容效果有限；低置信度不进入“今天最值得看”。

## ADR-004 JSON + Markdown，不上数据库

**背景**：单人、每天 10 条、保留 7 天原始视频，规模很小。

**决定**：用 JSON 状态文件记录处理状态，输出标准 Markdown + frontmatter。

**代价**：并发写入需要锁，复杂查询不如 SQLite；换来可直接检查、手工修复、无迁移负担。

## ADR-005 脚本不调用模型，宿主负责分析

**背景**：模型和采集器耦合会导致重跑成本高、输出不可检查、模型不可替换。

**决定**：采集器只产出证据包；分析由宿主按 `prompts/analyze.md` 完成，输出严格 JSON；渲染器只读 JSON。

**代价**：多一步编排；换来模型可替换、失败可单独重跑、输出可人工审阅。

## ADR-006 合成示例，不使用真实账号数据

**背景**：公开仓库一旦包含真实视频、OCR 原文或卡片，就可能涉及他人内容、账号信息和版权。

**决定**：公开示例全部合成，URL 使用占位 ID，作者为“示例作者”；demo 不访问网络。

**代价**：示例不如真实案例鲜活；换来可公开、可复现、无隐私风险。

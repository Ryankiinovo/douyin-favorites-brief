# 隐私与公开边界

## 1. 这个仓库处理什么数据

**不包含**：

- Cookie、sessionid、登录二维码、账号密码；
- 原始视频、关键帧、OCR 原文；
- 真实知识卡/日报、真实账号昵称；
- 本机路径、日志、API Key、通知 token；
- 采集器、登录器、OCR 编译产物。

**包含**：

- 产品定义、架构、决策、案例；
- 结构化提炼提示词与 JSON 契约；
- 渲染器与合成 demo；
- 合成示例。

## 2. 为什么采集层不公开

完整采集层依赖：

- 个人登录态（等同账号访问权）；
- 平台页面结构与风控策略；
- 本机 Chrome、ffmpeg、OCR 环境；
- 持续维护的页面适配。

把它包装成公开工具，会同时带来平台条款、账号安全、长期维护和“别人跑不起来”的承诺问题。因此公开层只展示**产品判断、契约、渲染和边界**，不提供采集器。

## 3. 私有运行环境的数据分级

| 数据 | 位置 | 敏感级别 | 保留 |
| --- | --- | --- | --- |
| 登录态（Cookie、Local Storage、History） | 私有运行目录 | **高**，等同账号访问权 | 直到手动重置 |
| 原始视频、关键帧 | 私有运行目录 | 中，含他人内容 | 默认 7 天 |
| OCR 文本、标题、作者、URL | 私有运行目录 | 中 | 7 天 / 随分析文件 |
| 分析结果 | 私有运行目录 | 中 | 随运行态 |
| 知识卡、日报、索引 | Obsidian vault | 中，长期 | 用户决定 |
| 通知摘要 | 私有运行目录 | 低–中 | 覆盖式 |
| 本机路径 | 本地配置 | 低–中 | 仅本机 |
| 日志 | 私有运行目录 | 低–中，可能含 URL/错误 | 手动清理 |

## 4. 私有环境的权限设计

- 运行脚本设置 `umask 077`，新建文件默认仅本人可读。
- 登录态目录创建时 `chmod 700`。
- 输出 Markdown 以 `0600` 写入，再由 Obsidian 正常读取。
- 写入先写临时文件再 `rename`，避免半截文件。
- 采集器只读收藏夹：不点赞、不关注、不评论、不发布、不改账号资料。

## 5. 主要风险

### 5.1 误提交

风险：`git add .` 把运行态、配置或日志提交。

控制：

- `.gitignore` 覆盖运行态、配置、日志、依赖；
- 首次提交前执行 `git status --short`；
- 不提交编译产物。

### 5.2 云同步

风险：把私有运行目录放进 iCloud/Dropbox，登录态被同步到云端。

控制：

- 私有运行目录不要放在云同步盘；
- Obsidian vault 可以同步，但运行态不要；
- 登录态只留在本机非同步目录。

### 5.3 截图/录屏

风险：演示时打开收藏夹或登录态目录，泄露账号信息。

控制：

- 演示用合成示例，不用真实账号；
- 必须展示真实界面时，先退出登录/遮住昵称；
- 不截运行态目录。

### 5.4 平台条款与风控

风险：高频采集触发验证码、限流或账号风险。

控制：

- 单人、每日 10 条、只读收藏夹；
- 不绕过验证码、不伪造 UA 规避风控；
- 遇到验证页停止，人工处理；
- 不把项目包装成公开采集服务。

### 5.5 模型与第三方

风险：把 OCR 文本/标题发给模型，可能包含他人内容或个人信息。

控制：

- 只发送生成摘要所需的字段；
- 不发送 Cookie、URL 中的 token、本机路径；
- 如果使用第三方模型，先确认其数据政策；
- 敏感内容可先脱敏，或只本地处理。

## 6. 如果登录态泄露

按顺序做：

1. 在平台 App/网页退出该设备会话，或修改密码；
2. 删除本机登录态目录；
3. 检查仓库历史是否提交过登录态；
4. 如果提交过，先轮换会话，再清理历史；仅删除当前文件不够；
5. 检查云同步/备份是否包含该目录；
6. 重新登录，确认旧会话已失效。

## 7. 分享边界

- 公开仓库只包含合成示例；
- 不把本地配置、运行态、日志打包发送；
- 如果要加真实案例，先获得内容作者/当事人的必要授权；
- 不添加“自动关注/点赞/评论/养号”等功能。

## 8. 边界声明

这是一个个人使用的本地自动化，不提供任何可用性、合规性或安全性保证。使用者需要自己确认：

- 所在地区/平台条款是否允许这种个人备份式处理；
- 采集频率是否合理；
- 输出内容是否涉及他人隐私或版权。

如果这些边界不能接受，就不要运行采集层。

# 产品定义（公开展示版）

> 原 PRD 是 2026-10-21 的内部版本；这里保留与公开展示相关的目标、范围、流程和验收标准，去掉个人环境与私有实现细节。

## 1. 一句话

把收藏夹里的新视频，自动变成每天一份可读的收藏日报和若干张可执行知识卡。

## 2. 目标用户

单人使用：重度收藏、低回看，已有 Obsidian 知识库和本地通知习惯，希望把“刷到的好内容”转成“可执行的输入”。

不是通用 SaaS，不做多租户、协作、账号体系。

## 3. 用户旅程

| 时刻 | 用户动作 | 系统结果 |
| --- | --- | --- |
| 白天刷到内容 | 点收藏 | 无感 |
| 次日早上 | 打开 Obsidian 或通知 | 看到昨天的收藏日报，先看“今天最值得看” |
| 读到某张卡 | 决定跟进/跳过 | 卡片状态可手工改为 read / actioned / archived |
| 登录过期 | 收到提醒 | 知道需要扫码，而不是以为任务正常 |
| 临时补跑 | 说“跑一次收藏提炼” | 立即执行一次，不重复处理已完成条目 |

## 4. 范围

### 做

- 从收藏夹读取新增视频，按平台 ID 去重；
- 下载视频、抽帧、提取字幕/OCR，形成证据包；
- 用严格 JSON 契约做结构化提炼；
- 渲染 Obsidian 源笔记、知识卡、日报、索引；
- 把日报摘要交给本地通知通道；
- 对登录失效、单条失败、模型漏条、渲染失败给出明确状态。

### 不做

- 不做公开采集服务或“养号”工具；
- 不自动点赞、关注、评论、发布；
- 不绕过验证码或平台风控；
- 不做多用户、权限、计费；
- 不在第一版接 ASR（保留扩展点）。

## 5. 功能需求（摘要）

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| FR-1 | 登录态检查 | 失效时停止并提示，不生成空结果 |
| FR-2 | 采集与去重 | 同一 `aweme_id` 只处理一次；同日重跑按日合并 |
| FR-3 | 证据提取 | 每条至少有标题、作者、时长、URL、字幕/OCR 之一 |
| FR-4 | 结构化提炼 | 输出字段完整、枚举合法、覆盖全部输入条目 |
| FR-5 | 渲染 | 生成源笔记、五字段卡片、日报、索引 |
| FR-6 | 失败隔离 | 单条失败不阻塞其他条目，进入日报的失败区 |
| FR-7 | 人工编辑保护 | 用户改过 status 的卡片不被覆盖 |
| FR-8 | 定时与通知 | 每日定时触发；最终回复为日报摘要 |
| FR-9 | 隐私 | 登录态、原始视频、日志不进入仓库或 Obsidian |

## 6. 数据契约

输入：`manifest.json` + `analysis_input.json`；输出：`analysis.json`。字段和枚举以 [prompts/analyze.md](../prompts/analyze.md) 与 [architecture.md](architecture.md) 为准。

关键约束：

- `verdict` 只能是四个枚举之一；
- `confidence` 非法时降级为 `low`，不阻塞渲染；
- `actions` 1–3 条，动词开头；
- `evidence` 必须来自输入，不改写、不编造；
- `items` 必须覆盖输入里的每个 ID。

## 7. 成功指标

第一版不追求“生成数量”，而看：

- 日报是否在早上 5 分钟内读完；
- 一周内真正打开/执行的卡片比例；
- 失败是否能在一个工作日内定位；
- 重跑是否会产生重复卡片或覆盖人工修改。

## 8. 风险与边界

| 风险 | 处理 |
| --- | --- |
| 登录态泄露 | 仅本机、权限最小化、绝不提交 |
| 平台条款/风控 | 单人、低频、只读；遇验证停止 |
| 他人内容/版权 | 原始视频短期保留；示例合成；不公开真实数据 |
| 模型幻觉 | 只依据输入；证据逐字引用；低置信度降级 |
| 采集层不可移植 | 公开展示层与私有采集层分离，不承诺一键复现 |
